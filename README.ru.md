# KAYOLAR V4 SPONGE

> [English](README.md) | [Français](README.fr.md) | [Español](README.es.md) | [Português](README.pt.md) | [Deutsch](README.de.md) | [Italiano](README.it.md) | [Русский](README.ru.md) | [中文](README.zh.md) | [日本語](README.ja.md) | [हिन्दी](README.hi.md) | [اردو](README.ur.md) | [Tagalog](README.tl.md)

Экспериментальная 344-битная хеш-функция: губка поверх новой 1024-битной ARX-перестановки. Все константы выводятся из 5 открытых чисел. Эталонная реализация на Rust.

    kayolar-hash-v4.0-sponge

> **Статус: экспериментальный.** Режим губки стандартный (его использует SHA-3); перестановка новая и не проходила независимого криптоанализа. Пока не используйте её для защиты реальных данных.

## Как это работает

- **Состояние**: 32 слова по 32 бита (1024 бита).
- **Впитывание**: каждый 64-байтный блок складывается по XOR с первыми 16 словами (rate), затем состояние переставляется. Остальные 16 слов (ёмкость, 512 бит) сообщение никогда не затрагивает и они никогда не выводятся.
- **Перестановка**: 18 раундов: прибавление константы; цепочка на месте `s[i] = rotl(s[i] * m[i], r) ^ s[i-1]` (изменённый бит достигает всех 32 слов за один раунд); перекрёстное сложение двух половин; циклический сдвиг массива на 3, 5 или 7 слов. Каждый шаг обратим.
- **Выход**: дополнение pad10*1, затем первые 43 байта rate.
- **Константы**: IV, 32 нечётных множителя и 18x32 раундовых константы получены из LCG на основе 111, 37, 163, 457 и 9.

Подробности: SPECIFICATION.md.

## Цели безопасности

| Атака | Общая стоимость (если перестановка надёжна) |
|---|---|
| Коллизия | 2^172 |
| Прообраз / второй прообраз | 2^256 |
| Удлинение сообщения | неприменимо |

Это стандартные границы для губки с ёмкостью 512 бит и выходом 344 бита. О самой перестановке они ничего не говорят: это открытый вопрос.

## Быстрый пример

    cargo build --release
    printf '' | ./target/release/kayolar_v4
    # 88141106867f261f24e022855d762fa6efc8efaf7466b5e93721449443c441347d461eb84f1bf845f9aeb6

    ./target/release/kayolar_v4 --string abc
    # 4c350f1fcb1d4cd486ba7e707a61ec29dff3801ca9acd0b810deed323eb5d9a082a77c70c506b7e89e647e

    ./target/release/kayolar_v4 --file path/to/file
    ./target/release/kayolar_v4 --stream 1000000 out.bin   # поток в режиме счётчика для статистических тестов

Как библиотека: `hashear_bytes(&data)`, `hashear("текст")` или `Hasher::new()` / `update()` / `finalize()` для потоков.

## Измерения (воспроизводимы в этом репозитории)

| Измерение | Результат |
|---|---|
| Перестановка биективна (10 000 состояний) | да |
| Полная диффузия перестановки | 3 раунда (используется 18) |
| Лавинный эффект, 2000 пар | среднее 172 ± 1,5 из 344 бит |
| Скорость, один поток | 52 МБ/с (SHA-256 с SHA-NI: 1342 МБ/с) |

KAYOLAR V4 примерно в 20 раз медленнее аппаратного SHA-256: цепочка на месте последовательна по замыслу.

## Персональные данные

Для псевдонимизации идентификаторов (телефон, e-mail, СНИЛС) одного хеша никогда не достаточно, какой бы ни была хеш-функция: значения с низкой энтропией восстанавливаются перебором. Используйте HMAC с ключом поверх стандартного примитива (SHA-256, SHA-3, BLAKE3, Стрибог).
